# Специфікація: портал пет-проєктів + Polyline-генератор доставок

Версія 1.0 · 23.11.2026 · узгоджено з Віталієм у треді проєкту

---

## 1. Портал пет-проєктів

### 1.1 Мета
Одна сторінка-індекс, з якої відкриваються всі пет-проєкти. Додавати нові проєкти просто, проєкти не впливають один на одного.

### 1.2 Архітектура
- **Монорепозиторій** на pnpm workspaces.
  ```
  apps/
    portal/      # індекс-сторінка
    polyline/    # перший проєкт
    <next>/      # наступні проєкти
  packages/
    ui/          # опційні спільні стилі/компоненти (необов'язкові для проєктів)
  projects.json  # реєстр проєктів: slug, назва, опис, іконка, статус
  ```
- Кожен застосунок має **власні залежності та окрему збірку** (Vite). Оновлення бібліотеки в одному проєкті не зачіпає інші.
- Збірка складає все в один статичний `dist/`: портал у корені, проєкти в `dist/<slug>/`.
- Портал рендерить картки з `projects.json`. Новий проєкт = нова папка в `apps/` + рядок у реєстрі.
- Усі застосунки працюють з **відносним base path**, щоб однаково відкриватися і в корені домену, і в підпапці (`username.github.io/<repo>/`).
- Бекенд за замовчуванням не потрібен. Якщо якомусь проєкту знадобиться сервер (наприклад, сховати API-ключ), для нього додається окремий Cloudflare Worker, не спільний.

### 1.3 Хостинг (обидва варіанти)
- **GitHub Pages**: GitHub Actions на push у `main` збирає і публікує `dist/`.
- **Cloudflare Pages**: підключення того самого репозиторію, та сама команда збірки, той самий `dist/`.
- Обидва безкоштовні; можна тримати паралельно. Власний домен — опційно, пізніше.

## 2. Polyline-генератор доставок (`apps/polyline`)

Сторінка з двох частин: **A — мапа та полілайн**, **B — таблиця замовлень (CSV)**.

### 2.1 Частина A: мапа і полілайн
- Мапа: **MapLibre GL або Leaflet + тайли OpenStreetMap** (без ключів і оплати).
- Формати вводу (поки лише два):
  1. **Encoded Polyline** (алгоритм Google), точність 5 за замовчуванням, перемикач на 6.
  2. **GeoJSON LineString coordinates**: масив `[[lng, lat], ...]`, також приймається повний об'єкт `{"type":"LineString","coordinates":[...]}`.
- Двосторонній зв'язок: зміна одного поля оновлює інше та лінію на мапі.
- Редагування на мапі за зразком Google Polyline Utility: клік додає вершину, перетягування рухає, видалення вершини.
- Валідація вводу з повідомленням про помилку.

### 2.2 Частина B: таблиця замовлень

#### Колонки за замовчуванням (у цьому порядку)
| Колонка | Значення при генерації | Редагування |
|---|---|---|
| `id` | порядковий номер | авто |
| `pickup_window_start` | поточний час, ISO 8601 з offset (`2021-09-22T00:00:00+09:00`) | так |
| `pickup_window_end` | start + 8 год | так |
| `dropoff_window_start` | = `pickup_window_start` | так, можна змінити незалежно |
| `dropoff_window_end` | = `pickup_window_end` | так, можна змінити незалежно |
| `pickup.address_en` | reverse geocoding англійською, інакше порожньо | так |
| `pickup.address_local` | reverse geocoding локальною мовою, інакше порожньо | так |
| `pickup.lng` | точка в зоні полілайну | так |
| `pickup.lat` | точка в зоні полілайну | так |
| `dropoff.address_en` | як для pickup | так |
| `dropoff.lng` | як для pickup | так |
| `dropoff.address_local` | як для pickup | так |
| `dropoff.lat` | як для pickup | так |
| `capacity` | порожньо | так |
| `contact_name` | порожньо або кнопка «згенерувати» | так |
| `contact_phone` | порожньо | так |
| `contact_email` | порожньо | так |
| `memo` | порожньо або кнопка «згенерувати» | так |

Порядок колонок узято точно з запиту (зокрема `dropoff.address_en, dropoff.lng, dropoff.address_local, dropoff.lat`). Колонки можна перетягувати.

#### Генерація рядків
- Кнопка **«+»** біля першого рядка додає один згенерований рядок; поряд поле **«згенерувати N рядків»**.
- **Зона полілайну**: точка випадково обирається вздовж лінії і зміщується перпендикулярно на відстань до **10 м** (налаштовується).
- **Pickup → dropoff**: dropoff лежить далі по лінії, ніж pickup; мінімальна відстань між ними вздовж лінії **2 км** (налаштовується). Якщо лінія коротша, показуємо попередження.
- **Часова зона** визначається автоматично за координатами полілайну (офлайн-бібліотека пошуку часової зони + `Intl` для offset з урахуванням літнього часу). Наприклад, Японія → `+09:00`. Зону можна змінити вручну.
- Параметри вікна (тривалість 8 год, старт = зараз) — у налаштуваннях генерації.

#### Reverse geocoding
- Сервіс: **Nominatim (OpenStreetMap)**, безкоштовний.
- Два запити на точку: `accept-language=en` → `address_en`; без мовного параметра (локальна назва) → `address_local`.
- Обмеження Nominatim: 1 запит/с. Тому черга запитів з прогресом, кеш результатів (за округленими координатами), таблиця заповнюється поступово, координати з'являються одразу.
- Помилка або відсутність результату → поле порожнє.

#### Дії в рядку
- **Перегенерувати pickup**: нові `pickup.lng/lat` + `pickup.address_en/local`.
- **Перегенерувати dropoff**: так само для dropoff.
- **Згенерувати ім'я** (`contact_name`): показує кілька англійських варіантів, користувач обирає один.
- **Згенерувати memo**: англійською, кілька варіантів шаблону на вибір, базовий:
  `I'm {contact_name}, I will be waiting for you at {pickup.address_en} between {pickup_window_start} and {pickup_window_end}.`
- **Ручні правки мають пріоритет**: клітинка, змінена вручну, позначається як ручна, і перегенерація її не перезаписує. Перезаписуються лише автозгенеровані значення.

#### Кастомні колонки
- Кнопка **«+»** у заголовку додає колонку; колонки можна перейменовувати та видаляти.
- **Схожі назви підсвічуються** (попередження): після нормалізації (нижній регістр, без `.`, `_`, `-`, пробілів) назви збігаються або відрізняються на 1–2 символи. Наприклад, `contactname` vs `contact_name`.
- Підсвітка зникає, щойно користувач перейменує колонку так, що вона більше не схожа.
- **Точний дублікат назви блокується** (не можна зберегти).

#### Мапа при наведенні на рядок
- Підсвічуються маркери pickup і dropoff та **відрізок самого полілайну між ними** (без зовнішнього роутингу).

#### Експорт і збереження
- **Експорт CSV**: роздільник кома, RFC 4180 (лапки для значень з комою/переносом), UTF-8.
- Автозбереження полілайну, таблиці та налаштувань у браузері (localStorage), щоб не губити роботу при перезавантаженні.

## 3. Поза рамками v1 (можна додати пізніше)
- Реальний маршрут через OSRM/OpenRouteService замість відрізка полілайну.
- Прив'язка точок до доріг.
- Google Geocoding / інші платні сервіси.
- Імпорт CSV для редагування.
- Генерація імен іншими мовами, збереження шаблонів наборів колонок.
- Інші формати вводу (Google Directions JSON тощо).

## 4. Технології
TypeScript, React + Vite, MapLibre GL / Leaflet, `@mapbox/polyline`, Turf.js (геометрія вздовж лінії), бібліотека пошуку часової зони за координатами, `@faker-js/faker` (англійські імена), pnpm workspaces.

## 5. Етапи
1. Каркас монорепо, портал з реєстром, деплой на GitHub Pages і Cloudflare Pages.
2. Частина A: мапа, encode/decode, GeoJSON, редагування на мапі.
3. Частина B: таблиця, генерація точок і вікон часу, часова зона, експорт CSV.
4. Nominatim з чергою і кешем, перегенерація pickup/dropoff, захист ручних правок.
5. Кастомні колонки з підсвіткою/блокуванням, генерація імен і memo, підсвітка маршруту при наведенні.
